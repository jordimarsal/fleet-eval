1. `collect_tables()` merges every `impl_*.md` globally into one dict keyed by bare identifier like "R12", with no link back to a feature; for any `--feature NAME` run, tests and Status from other specifications' tables are merged into the current feature's result, so coverage and done/unresolved verdicts are computed against the wrong requirement scope.
2. `test_identifier_exists()` passes when the identifier appears anywhere as a substring of any searched .py/.ts file contents (e.g. inside comments or strings) rather than being referenced as/an actual test artifact, silently converting broken references into passing checks; it also re-reads every candidate test file once per identifier instead of scanning each file once, causing O(identifiers × files) disk reads.
3. Both `collect_tables()` and `find_requirements()` propagate raw exceptions (corrupt UTF-8/large binary progress notes or path errors) instead of failing cleanly with context about which spec/table broke; a single malformed `harness/progress/*.md` aborts the whole traceability run across all features rather than reporting that one bad input.
