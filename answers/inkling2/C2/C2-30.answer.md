1. find_requirements path construction does not validate feature against directory traversal, so --feature values containing ../ or absolute path segments can make the tool read files outside harness/specs.
2. find_requirements silently returns an empty set when requirements.md is missing, conflating “no spec found” with “zero requirements” and producing misleading traceability results instead of a usage/error outcome.
3. REQ_RE matches any literal R<digits> anywhere in requirements.md prose or examples, so non-requirement mentions can be counted as required identifiers and create false coverage/gap decisions.
4. collect_tables signature is dict[str, dict[str, list[str]]] while its docstring says it merges tables into {requirement: [test identifiers]}, an inconsistent returned contract that later code will consume incorrectly.
5. ROW_RE only matches lines beginning immediately with | and captures at most the first two cells / second cell without embedded pipes, so valid indented markdown-table rows are ignored and parsed as gaps rather than covered.
6. read_text(encoding="utf-8") is applied without handling OSError/UnicodeDecodeError on requirements.md, so I/O or encoding failures escape as an unhandled crash rather than conforming to documented exit behavior.
