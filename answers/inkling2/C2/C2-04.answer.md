1. `probe()` — the per-iteration log read uses `open(log, errors="ignore").read()` without closing the handle; this leaks a file descriptio every polling iteration under long timeouts.
2. `health check / probe()` — success is inferred from HTTP readiness on the requested port with no verification that the listening service belongs to spawned process; stale or unrelated services/processes can make an over-sized context appear successful (or hide failure).
3. `probe()` / process-group handling — the harness deliberately creates a new session (`start_new_session=True`) but terminates only the direct child PID via `proc.terminate()/kill()`, not the process group, so launched children may survive after probing and keep memory/port occupied.
4. `main()`/port usage — fixed default port plus serial contexts are reused without checking ownership or detecting collisions between concurrent runs, which makes repeated measurements nondeterministic across processes.
5. `_argv_for()` — known short/long “ctx” flags are replaced by adjacent token replacement while unknown context flag spellings remain unchanged, leaving conflicting/unreplaced arguments rather than enforcing one canonical override for arbitrary model commands.
