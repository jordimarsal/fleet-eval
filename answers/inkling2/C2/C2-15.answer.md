1. `strata_python()` assumes a POSIX-style venv at `.venv/bin/python` and ignores valid Windows/other layouts such as `Scripts/python.exe` (or macOS variants with different entry points), making otherwise functional environments look absent.
2. `strata_python()` silently falls back to `sys.executable` when the venv is missing, which can launch the Strata server under an unpinned/unexpected interpreter instead of failing before spawning it.
3. The argv builder hardcodes `"--engine", "strata"` while the manager supports selectable engines, so any generic command-construction path cannot represent non-Strata configurations without overriding the selected engine.
4. `port=0` is treated like “unset” because of truthiness in `port or ...`, so an explicitly supplied falsy port is ignored rather than validated or honored consistently.
5. `context_mode` is stored unchecked despite being only meaningful for supported modes, allowing invalid values through construction where `engine` and `thinking` are rejected early.
6. `READY_TIMEOUT[engine]` relies on exact parity between `ENGINES` and `READY_TIMEOUT`; if a newly added engine lacks an entry, initialization raises a bare `KeyError` instead of a controlled validation error.
