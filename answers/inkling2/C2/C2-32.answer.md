1. `JSON.parse(event.data)` is unguarded, so a single malformed frame or empty body throws from inside an event listener and can kill that dispatch/handler flow instead of being handled as a stream error.
2. The parsed payload is blindly trusted via `as { seq: number }` / later `as StreamFrame` without checking shape or types, so frames lacking a numeric `seq` or required fields will crash downstream consumers rather than fail cleanly at the boundary.
3. Gap detection assumes every subscribed name carries a monotonically increasing integer `seq`; `heartbeat`/duplicate-style frames likely have different shapes, so comparisons on undefined/non-numeric values produce wrong gap decisions and corrupt `lastSeq`.
4. Frames with `parsed.seq <= lastSeq` are still passed to `onFrame` unconditionally, so replayed/duplicated old data is reprocessed even though sequence state shows it was already seen.
5. `lastSeq` is never reset/reconciled across reconnections or server restarts (e.g. fresh sequence space after a failed connect), so stale state creates false gaps or misses real ones and does not implement Last-Event-ID resume behavior.
6. `source.onerror = () => handlers.onStatus('reconnecting')` reports “reconnecting” regardless of whether EventSource has actually terminated (terminal close, fatal error, exceeding browser retry limits), making status truthfully inaccurate during permanent failure.
7. The returned cleanup only calls `source.close()` with no listener teardown beyond that and no protection against late events/handler callbacks racing client disconnect, leaving callers unable to guarantee quiet shutdown semantics.
8. Default factory casts native DOM EventSource through `as unknown as EventSourceLike` despite the interface’s narrower typing; this erases the event parameter difference instead of normalizing it in an explicit adapter, hiding contract drift between runtime source and interface.
