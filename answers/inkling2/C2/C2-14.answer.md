1. `_probe_sandbox` — missing `except OSError`/`FileNotFoundError` means a host where the `unshare` binary is absent or launch fails propagates an exception instead of reporting “not available” and letting callers fall back cleanly.
2. `_probe_sandbox` — fail-open behavior after an availability probe failure returns an unrestricted command prefix rather than raising/refusing, so a required confinement policy appears satisfied even when nothing was isolated.
3. `_safe_run` — returning only `None` for timeout loses partial output plus exit status, so callers cannot distinguish “killed midway with useful partial result” from hard failure and must re-derive state that may already be lost.
4. `_safe_run` / prefix layering — relying on both inner per-process enforcement and outer `timeout … unshare … cmd` wrapping does not reliably guarantee descendant processes are terminated or reaped on deadline expiry, which can leak background workers or leave namespaces alive.
5. `_sandbox_prefix` — `_probe_sandbox()` is invoked every invocation (rather than reasoning about one stable verdict), adding repeated subprocesses per run and creating stale-result risk between probing time and execution time; any cached decision made elsewhere risks disagreeing with the actual environment.
