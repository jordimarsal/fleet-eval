1. connectStream: `JSON.parse(event.data)` is uncaught, so malformed server payload throws inside the native event dispatch path and can kill handling for subsequent frames/handlers; errors are neither handled nor surfaced through a status/gap channel.
2. connectStream: the unchecked cast of parsed data to `{ seq: number }` accepts missing/non-numeric seq (including NaN), making gap detection silently nonfunctional instead of failing fast or treating it as corrupt.
3. connectStream: one shared `lastSeq` across all EVENT_NAMES assumes telemetry/duplicate/alert/dlt/heartbeat share a single global monotonic sequence; if those topics have independent cursors this produces false gaps or hides real ones.
4. connectStream: `onGap` is skipped on first frame because `lastSeq > 0` gate suppresses initial validation, so sequence discontinuity at connection start / after reconnect from a later offset goes unreported.
5. connectStream: partial parse failure/ordering state is not reset on reconnect/server restart/resume; a stale `lastSeq` either reports false gaps or swallows true ones across source replacement boundaries.
6. addEventListener listener closure: downstream `handlers.onFrame/onStatus/onGap` throwing is also unguarded inside dispatcher context; one bad handler can break subsequent event processing and leave connection/status reporting inconsistent.
7. cleanup returned by connectStream only calls `source.close()` without removing listeners or invalidating the callback path, leaving captured `handlers`/closures alive beyond teardown and allowing late status updates after close (race) rather than cleanly quiescing the stream.
8. StreamHandlers contract mismatch: frames are emitted for every EVENT_NAMES including heartbeat with no schema/shape validation per kind, so consumers of typed `StreamFrame` receive unchecked payloads that may violate required fields or invariants.
9. Connect/reconnect behavior ignores EventSource's native resume/Last-Event-ID mechanics and app-level sequence cursor properly: standard reconnection metadata is ignored while application owns gap detection, making duplicates/gap recovery reliant on fragile manual seq comparison rather than protocol state.
10. Error semantics conflate transient disconnect and terminal failure: any `source.onerror` sets `onStatus('reconnecting')` even for a permanently failed source, so UI cannot distinguish recoverable from dead streams.
