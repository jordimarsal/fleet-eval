1. Line ~211 `elif [ -n "$DISCOVERED_NETWORK" ]` reads an otherwise unguarded unset variable while neighboring checks use `${VAR:-}`, so under a nounset shell (likely with pipefail in this project) the script aborts whenever discovery did not populate DISCOVERED_NETWORK.
2. The final case branch executes `[ "$(uname -s)" = "Linux" ] && NET_ARGS=(--network=host)` as a bare statement; on macOS/BSD the test status becomes nonzero, which can trip set -e even though host networking is simply intended absent there.
3. Localhost detection only matches literal scheme + `localhost` or `127.0.0.1` prefixes, so equivalent local endpoints such as `http://[::1]:9000`, `*.localhost`, or other loopback forms are treated as external hosts and launched into isolated bridge networking where they cannot be reached.
4. On non-Linux with a localhost SONAR_HOST_URL, no Docker workaround is supplied (no extra host mapping/gateway/published port), leaving the container pointing at its own loopback and breaking the documented local mode instead of failing early with a clear reason.
5. CACHE_DIR from `SONAR_SCANNER_CACHE` is mounted to /opt/sonar-scanner/.sonar without requiring an absolute path or canonicalizing it; a relative cache path produces a Docker volume error rather than a meaningful validation message from the script.
6. The default image tag is just `sonarsource/sonar-scanner-cli` (implicit latest, unpinned digest), making builds nondeterministic and supplying whatever upstream publishes by scan time — a broken reproducibility/integrity contract for CI checks.
7. Shared on-disk scanner state under one CACHE_DIR has no locking/per-run subdirectory, so concurrent runs can interleave/corrupt credentials/cache files in that shared mount.
