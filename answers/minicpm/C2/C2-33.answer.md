2. `connectStream`: There is no error handling for network failures beyond triggering `onStatus('reconnecting')`; the `EventSource` connection may silently fail or hang without retry logic or timeout mechanisms.
3. `connectStream`: The `lastSeq` variable is initialized to 0, which means the first valid event with `seq: 0` will not trigger a gap detection even if it's unexpected, and `seq: 1` will be treated as a normal progression, potentially masking initial sequence issues.
4. `connectStream`: The `open` parameter defaults to creating a new `EventSource` with a relative URL `/api/v1/stream`, but in some deployment configurations (e.g., different origins or proxy setups), this might require absolute URLs or specific headers that are not supported by the current abstraction.
5. `connectStream`: The returned cleanup function only calls `source.close()`, but does not remove the event listeners explicitly, which could lead to memory leaks if the component unmounts and remounts rapidly while the EventSource is still closing asynchronously.
