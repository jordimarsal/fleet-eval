1. `connectStream` / `for (const name of EVENT_NAMES)` loop: `JSON.parse` is called without a try-catch block, so any malformed or non-JSON payload from the server will throw an unhandled exception that crashes the event listener and potentially breaks the connection state handling.
2. `connectStream` / `source.onopen`: The `onopen` handler sets status to `'live'` but does not reset `lastSeq`, which means if the client reconnects after a disconnect, the gap detection logic will incorrectly compare new sequence numbers against stale ones from the previous session.
3. `connectStream` / `source.onerror`: Setting status to `'reconnecting'` on error is misleading because standard `EventSource` behavior automatically attempts reconnection internally; this handler implies manual retry logic or a different state machine than what the browser provides, potentially causing UI confusion about actual connection availability.
4. `connectStream` / `parsed.seq > lastSeq + 1`: The gap detection condition assumes that `seq` values are strictly sequential integers incremented by 1, but if the server uses sparse sequence numbers or non-integer IDs, this logic will falsely trigger `onGap()` for valid sequences.
5. `connectStream` / `handlers.onFrame({ kind: name, ...parsed } as StreamFrame)`: The code casts the parsed JSON object directly to `StreamFrame` without validating that the parsed data actually conforms to the expected `StreamFrame` interface, which could lead to runtime errors or undefined behavior if the server sends unexpected fields.
6. `connectStream` / `return () => source.close()`: If `open()` throws an exception (e.g., due to invalid URL or blocked network), `source` is never assigned, and the returned cleanup function will attempt to call `close()` on `undefined`, causing a runtime TypeError.
7. `addEventListener` interface definition: The `listener` parameter type `(event: { data: string }) => void` is overly narrow compared to the standard `EventSource.addEventListener` signature which expects an `EventSourceMessageEvent`, potentially causing TypeScript compatibility issues or hiding other useful event properties like `lastEventId`.
