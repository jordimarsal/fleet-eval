1. `byLabel`: The comparison `POOL[i].t === kv[1]` fails if the query parameter value contains a trailing comma or extra whitespace because `split(",")` does not trim values, causing valid deep links to resolve to index -1 instead of the correct pool item.
2. `sync`: The URL parameters are constructed by concatenating `s` and `t` with a literal comma (`","`) before encoding, but `byLabel` splits on commas; if either `s` or `t` ever contains a comma character itself, the round-trip parsing in `byLabel` will break due to ambiguous delimiters.
3. `render`: The function assumes that `selA.value` and `selB.value` always correspond to valid indices in the `POOL` array (via `POOL[selA.value]`), but if the DOM selects an option manually or via a stale hash before initialization completes, or if `POOL` is empty, `A` or `B` can be undefined, leading to runtime errors in `mixedBanner`, `card`, or `sections`.
4. `changed`: The event listener calls `sync()` which updates the history state, but it does not handle the case where `selA` or `selB` might have been programmatically set to an invalid value (e.g., `-1` from a failed lookup elsewhere) before `render()` is called, potentially causing `POOL[-1]` access inside `sync`'s string construction.
