1. `connectStream`: The `onerror` handler unconditionally sets status to 'reconnecting', failing to distinguish between transient network blips where the browser will auto-retry successfully and permanent failures (e.g., HTTP 4xx/5xx), potentially leaving the UI in an incorrect state if the connection drops permanently without closing.
2. `connectStream`: The gap detection logic (`if (lastSeq > 0 && parsed.seq > lastSeq + 1)`) assumes that sequence numbers are strictly contiguous across all event types, but since listeners are registered for multiple distinct event streams (`telemetry`, `alert`, etc.) sharing a single `lastSeq` variable, interleaved events from different sources will cause false positive gap alerts unless the server guarantees a global monotonic counter across all emitted event types.
3. `connectStream`: The `JSON.parse(event.data)` call lacks error handling, meaning any malformed JSON payload from the server will throw an unhandled exception inside the event listener, which can halt further processing of subsequent frames for that specific event type or crash the application depending on the environment's error boundary configuration.
4. `connectStream`: The function returns a cleanup closure that calls `source.close()`, but it does not remove the event listeners attached via `addEventListener`, nor does it clear the `onopen`/`onerror` properties; while `close()` typically handles this in modern browsers, relying solely on `close()` without explicit listener removal is fragile against non-standard implementations or if the source object is reused/reconnected elsewhere, and more critically, it leaves the `handlers` object referenced by the closures until garbage collection, preventing the parent component from being unmounted cleanly if it holds strong references to those handlers.
