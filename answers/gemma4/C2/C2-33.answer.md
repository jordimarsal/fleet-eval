1. `connectStream`: The `source.onerror` handler sets status to 'reconnecting' but does not implement any retry logic or handle terminal error states, potentially leaving the UI in a permanent "reconnecting" state if the connection fails permanently.
2. `connectStream`: The `lastSeq` variable is initialized to `0`, which will trigger a false positive `handlers.onGap()` call on the very first message received if that message's sequence number is greater than 1.
3. `connectStream`: The `JSON.parse(event.data)` call lacks a try-catch block, meaning a single malformed JSON payload from the server will crash the entire event listener loop and stop telemetry processing.
4. `connectStream`: The type assertion `as StreamFrame` is unsafe because it assumes all events in `EVENT_NAMES` share the same schema as `{ seq: number }`, which may lead to runtime errors if different event types have different required properties.
5. `connectStream`: There is no mechanism to reset `lastSeq` when the connection closes and reopens, leading to incorrect gap detection and sequence validation upon reconnection.
