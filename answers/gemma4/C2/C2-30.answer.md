1. `find_requirements`: The regex `REQ_RE` uses `\b`, which will fail to match requirements if they are immediately followed by punctuation other than word characters (e.g., `"R1."` or `"R1,"`).
2. `find_requirements`: The function returns an empty set if the file does not exist, which prevents the caller from distinguishing between a feature with no requirements and a missing/invalid specification file.
3. `collect_tables`: The docstring claims to merge tables into `{requirement: [test identifiers]}`, but the return type hint specifies `dict[str, dict[str, list[str]]]`, creating a contract mismatch.
4. `collect_tables`: The implementation lacks error handling for `root / "harness" / "progress"` being a file instead of a directory, which would cause `is_dir()` to pass but subsequent operations to potentially fail depending on how `progress` is used later.
5. `find_requirements`: Calling `req_file.read_text()` without a try-except block will cause the entire script to crash with an unhandled exception if the file exists but the user lacks read permissions.
