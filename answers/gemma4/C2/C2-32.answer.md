1. `connectStream`: If `JSON.parse` fails due to malformed data, the error will propagate unhandled, potentially crashing the execution context or leaving the stream in an inconsistent state.
2. `connectStream`: The `onerror` handler only triggers `handlers.onStatus('reconnecting')` but does not implement any retry logic or attempt to re-establish the connection via the `open` factory.
3. `connectStream`: There is no mechanism to handle sequence number resets or wraps, which will cause `handlers.onGap()` to trigger incorrectly if the backend restarts its sequence from zero.
4. `connectStream`: The `lastSeq` variable is captured in a closure but is not reset if the connection is closed and a new one is opened via subsequent calls to `connectStream`, leading to incorrect gap detection across sessions.
5. `connectStream`: The implementation assumes all events in `EVENT_NAMES` contain a valid `seq` property in their JSON payload, which violates type safety if any event type (like `heartbeat`) lacks this field.
6. `connectStream`: The returned cleanup function closes the `source` but does not nullify references or clear the event listeners, which can lead to memory leaks in certain environments if the `handlers` object holds large closures.
