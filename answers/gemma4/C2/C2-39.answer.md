1. `EstolApp`: The `refresh` function launches a coroutine in `scope` (the composition scope) without checking if the component is still active, which can lead to state updates on a destroyed composition.
2. `EstolApp`: `Settings.loadNodes(context)` is called directly during the initial composition, which performs blocking I/O on the Main thread and will cause UI jank or ANRs.
3. `EstolApp`: The `refresh` function uses `withContext(Dispatchers.IO)` but does not handle potential exceptions thrown by `Fleet.status(node)`, which could crash the application if `runCatching` were absent or if other logic within the block fails.
4. `EstolApp`: There is no mechanism to cancel ongoing `refresh` jobs, meaning multiple rapid calls to `refresh` will trigger concurrent network/IO operations that race to update the `statuses` state.
