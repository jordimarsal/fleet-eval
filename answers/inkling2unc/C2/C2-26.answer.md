1. Settings.model_config.env_file: `".env"` is resolved relative to the process working directory, so running from a different cwd silently drops configured values and falls back to defaults instead of failing fast.
2. Settings.model_config extra="ignore": unknown or misspelled CODERAG_* variables are discarded without error, masking config mistakes and making deployments run with unintended defaults.
3. Settings.database_dsn: keeping the DSN in plain `str` means credentials embedded in it can appear verbatim in reprs/logs and need secret handling such as SecretStr rather than being treated as non-sensitive text.
4. Settings.database_dsn/embedder_url: both URL/DSN fields accept any arbitrary string with no scheme/host/port validation, so startup succeeds even when database or embedder endpoints are malformed and failures surface only later at use time.
5. Settings.chunk_size: the unconstrained int default allows zero, negative, or impractically large chunk sizes, breaking downstream splitters and retrieval assumptions that require a positive bounded window.
6. Settings.repo: defaulting to `"."` makes index/retrieval operate on whatever repository happens to be the current working tree, which can silently change scope across entry points or edit operations.
7. Settings.retrieval_strategy/bm25_backend: free-form strings for strategy and BM25 backend permit typos and inconsistent pairs (e.g. hybrid strategy with memory BM25) to pass validation even though downstream behavior depends on an explicit compatible mode.
