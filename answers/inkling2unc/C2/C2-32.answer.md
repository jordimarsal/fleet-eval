1. connectStream / onopen->status mapping: native EventSource closes without firing a terminal onerror after giving up reconnecting, so status is stuck at 'reconnecting' forever on fatal failure.
2. source.onerror = ... always sets 'reconnecting' even when the stream never opened or is permanently failed, misrepresenting connection state instead of distinguishing first-failure from active reconnect backoff.
3. The per-name event listener block calls JSON.parse(event.data) with no try/catch, so any malformed payload throws inside the listener and leaves the frame undispatched while potentially spamming console errors rather than being surfaced via handlers.
4. `parsed` is cast to `{ seq: number }` without validating seq exists/is numeric; if it is missing or non-numeric, comparisons like `parsed.seq > lastSeq + 1` are falsey and `lastSeq` can silently stop tracking, corrupting gap detection and ordering assumptions downstream.
5. Gap reporting uses cumulative lastSeq across all five named events but does not report/acknowledge the actual jump width (only one boolean onGap call for arbitrary gaps) nor reset lastSeq on close, so cleanup followed by reconnect reuses stale sequence state rather than starting fresh.
6. Return cleanup only calls source.close() and removes nothing else; references retained and any in-flight/late event callbacks after close can still dispatch frames into the old handler closure unless handlers treat a closed stream as cancelled.
