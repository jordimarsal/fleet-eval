1. `find_requirements` silently treats a missing/empty requirements file as an empty-but-valid task instead of distinguishing malformed input, making feature errors look like perfectly clean rows and violating the intended usage-error distinction implied by exit codes.
2. `find_requirements` path construction lacks validation for `feature`: whitespace, separators, relative parent paths, or absolute values can alter the resolved location outside the intended `harness/specs/<NAME>` tree (a fully absolute value even replaces root) and therefore read unexpected files.
3. `REQ_RE` scans arbitrary prose rather than identifying declared requirement definitions, so references, examples, notes, or other tokens matching `R<digits>` become “required” IDs independent of whether they are real requirements.
4. `ROW_RE` relies on exact column placement under no multiline flag, omitting support for indented tables and being unanchored/lenient around row boundaries; thus valid rows may be missed while otherwise irrelevant first-column text is consumed as test metadata without checking what the captured cell actually contains.
