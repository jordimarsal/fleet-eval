Root cause: `find_open_episode()` returns a completed episode log when multiple tests share the same `BW_DEBRIEF_ROOT` directory (e.g., `/home/jordi/.../artifacts/demo/exec20261115T1623Z/f2_hub.log`). The function only checks for `result:` presence but does not verify that the episode belongs to the current test's run — it resumes any matching file regardless of whether it was written by a previous test invocation. Since all three failing tests use the fixture-generated project name `"demo"` and the developer has `BW_DEBRIEF_ROOT` set globally, each subsequent test finds the prior test's finished log and attempts to append steps to an already-finished episode.

The minimal fix is in `_resume()`: after detecting `result:`, also verify the episode is still open by checking that no step lines exist beyond what this invocation would produce, or better yet, add a guard in `step()` to reject resuming logs where the ordinal count exceeds expectations. However, the cleanest approach is to make `find_open_episode()` stricter: require that the resumed log's last step ordinal matches what we'd expect from a fresh start, OR simply refuse to resume if the log contains `result:` AND has more than zero steps (indicating it was completed by another process). 

Actually, the simplest correct change: modify `_resume()` to raise when `result:` exists alongside non-empty `_steps`, since a legitimately unfinished episode should never have both. This catches cross-test contamination without changing the public API.
