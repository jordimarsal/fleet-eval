1. `connectStream` — The `source` variable created by `open()` is never closed when an error occurs; only the returned cleanup function closes it, so errors that prevent further processing leak the EventSource connection.
2. `connectStream` — The `onerror` handler sets status to `'reconnecting'` but does not trigger any reconnection logic, leaving the stream permanently in a broken state after the first network failure.
3. `connectStream` — `JSON.parse(event.data)` will throw if the server sends malformed JSON, crashing the entire SSE listener with no try/catch protection.
4. `connectStream` — The `lastSeq > 0 && parsed.seq > lastSeq + 1` gap detection fires `handlers.onGap()` for every out-of-order event without deduplication, potentially flooding handlers with repeated gap notifications.
5. `connectStream` — If `parsed.seq < lastSeq`, the code silently drops the event without calling any handler, violating the contract that all events should be delivered (or at least logged).
6. `connectStream` — The `as unknown as EventSourceLike` cast bypasses TypeScript's type safety on `EventSource` properties like `onopen` and `onerror`, which may have incompatible signatures between DOM types and the custom interface, causing runtime failures.
7. `connectStream` — Multiple calls to `connectStream` create independent `EventSource` instances sharing the same URL `/api/v1/stream` without any cleanup of previous connections, leading to resource leaks when callers don't invoke the returned cleanup function.
8. `connectStream` — The `EVENT_NAMES` array is hardcoded but there's no mechanism to add or remove listeners dynamically, making it impossible to handle new event types without modifying this file.
