1. `collect_tables` — The regex `ROW_RE` uses greedy `[^|]*` groups that match across multiple table columns, causing incorrect parsing when rows contain pipe characters within cell content (e.g., markdown tables with embedded pipes in test identifiers).
2. `collect_tables` — When a requirement appears in multiple impl_*.md files, only the first-seen status is retained via `statuses.setdefault`, silently discarding potentially more accurate or updated status from later implementations without any warning or merge logic.
3. `test_identifier_exists` — Reading every file under tests/ and src/ into memory for each identifier lookup causes O(n*m) complexity where n is the number of identifiers and m is the total size of all test files; this will hang or timeout on large codebases.
4. `test_identifier_exists` — The substring search (`identifier in tf.read_text(...)`) produces false positives by matching partial strings; e.g., searching for "R5" would match any file containing "R50", "R51", etc., incorrectly validating requirements.
5. `test_identifier_exists` — The function reads entire files into memory repeatedly for each identifier check, creating unnecessary I/O overhead and potential resource exhaustion on systems with many small test files.
6. `COMMAND_RE` — The regex pattern uses `\b` word boundary after command names but doesn't anchor to start-of-string properly combined with the full string match, allowing commands like "npmx run foo" to pass validation since "npm" matches at position 0 with a word boundary before 'x'.
7. `collect_tables` — The function returns empty dicts when progress directory doesn't exist, but callers have no way to distinguish between "no implementations yet" and "progress directory missing due to error," potentially masking configuration issues.
8. `find_requirements` — Uses `REQ_RE.findall()` which finds ALL R\d+ patterns including those inside comments, headings, or other non-requirement contexts, leading to inflated requirement counts that don't reflect actual spec requirements.
9. `check_feature` — Returns an incomplete dict (only has `requirements`, `tables`, `statuses`) without actually performing the traceability checks described in the docstring, making it unclear what data consumers should expect.
10. `test_identifier_exists` — The `errors="replace"` parameter silently corrupts file content during reading, potentially causing false negatives where valid identifiers are mangled by replacement characters in binary or malformed text files.
