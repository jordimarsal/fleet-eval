1. `_probe_sandbox` sets `SANDBOX_AVAILABLE` as a module-level variable but never declares it with `global SANDBOX_AVAILABLE`, so the assignment silently creates a local variable that shadows the global and leaves the global unchanged (always `False`).
2. `_sandbox_prefix` calls `_probe_sandbox()` on every invocation instead of caching its result, causing repeated subprocess forks for each benchmark run.
3. `_safe_run` ignores all non-timeout exceptions from `subprocess.run` (e.g., `FileNotFoundError`, `PermissionError`) by catching only `TimeoutExpired`, which means callers receive an unexpected exception rather than a controlled error signal.
4. `_safe_run` returns the full `CompletedProcess` object on success without extracting stdout/stderr, forcing callers to access `.stdout`/`.stderr` manually while also leaking the raw process metadata.
5. The `timeout` parameter in `_probe_sandbox` defaults to `None` via `subprocess.run`'s default, meaning sandbox probing can hang indefinitely if `unshare` itself blocks waiting for resources.
6. `_sandbox_prefix` uses `unshare -Urn` which requires either root or user namespace support; on kernels without `CONFIG_USER_NS=y` or when `kernel.unprivileged_userns_clone=0`, this silently falls back to no sandboxing without any warning.
7. `_safe_run` does not propagate `cwd` validation—if the directory doesn't exist, `subprocess.run` raises `FileNotFoundError` which is swallowed as `None`, making debugging extremely difficult.
8. The module-level `SANDBOX_AVAILABLE = False` at line 1 is dead code since it's immediately shadowed by the local assignment inside `_probe_sandbox` (see defect #1).
