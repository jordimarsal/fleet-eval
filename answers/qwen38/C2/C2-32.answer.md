1. `connectStream`: The `onerror` handler unconditionally sets status to 'reconnecting', which incorrectly reports reconnection attempts even when the connection has permanently failed or been closed by the user, violating the expected state machine semantics.
2. `connectStream`: The cleanup function returned does not remove the registered event listeners (`source.removeEventListener`) before closing, potentially causing memory leaks or dangling references if the `EventSourceLike` implementation retains listener handles after `close()` in certain environments or wrappers.
3. `connectStream`: The gap detection logic assumes that sequence numbers are strictly contiguous across all event types combined, but since multiple named events share the same `lastSeq` counter without distinguishing streams, interleaved events from different categories may cause false positive gaps or incorrect sequence tracking if the server assigns global sequences differently than assumed.
4. `connectStream`: The cast `as StreamFrame` on the spread object `{ kind: name, ...parsed }` bypasses type safety for fields other than `seq`, allowing malformed or unexpected JSON payloads to pass through as valid frames without validation of required properties specific to each `kind`.
5. `connectStream`: There is no handling for `JSON.parse` failures; if `event.data` contains invalid JSON (e.g., due to network corruption or partial transmission), an unhandled exception will be thrown inside the event listener, breaking the stream processing loop and preventing subsequent events from being handled.
